# ADR 0010: 로봇 관측과 운영 기록

상태: 채택

로봇 화면에서 현재 자세와 과거 가동 상태를 함께 확인해야 합니다. 기존 Gateway는
Mission lifecycle을 소유하며 배터리, 관절과 Supervisor 상세 관측을 전달하지 않습니다.

관측 전용 `robot-observation.schema.json`과 인증된 WebSocket을 추가합니다. 관측은
Mission FSM 또는 명령 경로를 변경하지 않습니다. ROS의 `cleany_telemetry`는 원본
관측을 만들고 `cleany_control_bridge`는 장치 인증과 저장 ACK, 재연결을 소유합니다.
Backend는 고객, 시설, 로봇 범위로 최신 값과 배터리, 활동 구간, 운영 이벤트를 저장합니다.

원본 ROS 시각과 이미 경과한 나이를 전달하고 Backend 수신 시각, 만료 시각을 별도로
기록합니다. 서로 다른 시계의 절대 시각을 직접 비교하지 않습니다. 관절별 원본 나이를
유지하여 바퀴 입력이 팔 데이터의 유효기간을 연장하지 않게 합니다. 명령 목표는 별도
종류이며 3D 자세에 사용하지 않습니다. 재시작 이후 최신 값은 마지막 관측으로 남고,
새 연결과 새 표본을 받기 전에는 실시간으로 표시하지 않습니다.

운영 기록은 기존 SQLite의 별도 테이블에 저장합니다. 고주파 관절 전체를 이력으로
쌓지 않고 최신 값만 저장합니다. 배터리는 설정 간격과 충전 변화 시 저장하고, 활동은
같은 상태가 이어지는 구간을 합칩니다. 유효 관측이 없는 구간은 미수신입니다. 분석은
최대31일, 배터리 최대480개 시간 구간, 이벤트100개 단위 cursor를 사용합니다.
실측, 시뮬레이션, 예시 출처를 보존하며 과거 Mission으로 배터리나 관절을 추정하지 않습니다.

브라우저는 별도 관측 Query를 사용합니다. 기존 Mission SSE에 고주파 관절을 넣지 않습니다.
CAD의 색상별 합본은 관절을 움직일 수 없으므로 같은 고정 원본에서 몸체별 파생 GLB를
만듭니다. 원본 CAD와 기존 정적 모델은 보존합니다. 관절 계산을 원본 MuJoCo FK와 비교하되
이는 실제 장치의 영점, 배선, 캘리브레이션 검증을 대신하지 않습니다.

조종 모드 진입은 서버의 연결, 준비, 정지 확인과 차단 사유를 확인합니다. 진입 자체는
명령을 보내지 않습니다. 기존 명령마다의 미션 admission lock, lease, watchdog,
release/blur/navigation STOP을 유지합니다. Supervisor/safety 관측이 설정된 뒤에는
오래된 관측, 장애 잠금과 물리 비상정지를 추가로 차단합니다. STOP은 이 차단을 우회합니다.
관측 채널은 Supervisor의 복구 실행이나 Robot 내부 FSM 변경 권한을 갖지 않습니다.

배터리 수집 이전 기록은 복원하지 않습니다. 이벤트 버퍼는 제한되며 장시간 단절 시
만료된 이벤트는 버리고 손실을 bridge 로그로 보고합니다. 이것은 손실 없는 감사 로그가
아닙니다. ROS가 아닌 외부 장치와 새로운 모델은 동일 계약의 별도 adapter가 필요합니다.
