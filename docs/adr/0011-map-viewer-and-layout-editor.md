# ADR 0011 — 운영 지도와 좌석 배치 편집기 분리

- 상태: 구현
- 날짜: 2026-11-17

## 문제

운영 지도 안에서 배치를 편집하면 floating 패널이 조작할 좌석을 가리고 운영 조회와
좌표 변경의 경계가 흐려진다. 개별 좌표 입력만으로는 여러 좌석을 함께 배치하기 어렵다.

## 결정

`/map`은 조회·작업 요청을 유지하고 `/map/edit`를 독립 편집 작업공간으로 둔다.
편집기만 툴바와 캔버스 옆 속성 패널을 사용한다. 공통 `SlamMapViewport`와
`SeatLayoutLayer`를 추출해 SLAM 레이어 혼합·좌표 변환·좌석 기하를 중복 구현하지 않는다.
기존 React/SVG 포인터 이벤트를 재사용하며 별도 캔버스 편집 라이브러리는 추가하지 않는다.

편집본은 페이지 로컬 상태와 최대80개 연산의 Undo/Redo 이력으로 관리한다. 드래그 중에는
미리보기만 바꾸고 놓을 때 한 연산을 기록한다. 좌석 이동/회전은 접근점을 함께 변환하며
접근점 모드는 목표만 변경한다. 변경 요약을 검토한 후 기존 revision 기반 PUT API로 저장한다.
성공 응답을 조회와 공유하는 Query 캐시에 넣으며 오류 시 편집본을 유지한다.

브라우저 뒤로/앞으로도 보호하기 위해 React Router의 `createBrowserRouter`와
`useBlocker`를 사용한다. 기존 Provider 순서와 경로는 유지한다. 창 닫기/새로고침에는
`beforeunload`, 라우터를 거치지 않는 층 변경/로그아웃에는 AppShell의 이탈 guard를 적용한다.
시설 변경은 history index/key를 보존하고 편집 진입/종료 링크는 site query를 유지한다.

## 결과와 검증

기존 지도·좌석 API와 데이터 schema는 변경하지 않는다. 저장은 모든 접근점과 복귀점의
현장 검증 상태를 해제하며 로봇 명령이나 로봇 내부 상태를 바꾸지 않는다. 인증 만료 후
미저장 편집본 복구나 여러 사용자 동시 편집 병합은 제공하지 않는다. revision 충돌은
기존 서버 오류를 표시하고 사용자가 변경 취소로 최신본을 다시 불러올 수 있다.

순수 좌표 연산·이력 단위 검사, 실제 격리 API 저장/오류와 이탈 보호 E2E, 기존 운영 탭과
0픽셀 시각 회귀를 실행한다. 편집 화면은1920/1366/1024px에서 패널 비중첩을 확인한다.
이 검증은 UI와 계약 검증이며 물리 로봇 주행·접근 검증을 대신하지 않는다.
