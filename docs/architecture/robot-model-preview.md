# Cleany 3D 모델 실험 변경 내역

작성일: 2026-09-08\
브랜치: `feat/robot-model-preview`

## 1. 목적과 현재 결론

Cleany의 실제 CAD 형상을 웹에 활용해 시각적 완성도를 높이는 실험이다.
처음에는 사용자가 회전·확대하며 둘러보는 모델 뷰어까지 구현했으나,
사용자가 원한 범위보다 커져 기존 대시보드 브랜치에서 분리했다.

**홈 로봇 목록 오른편에 작은 외형 프리뷰를, 로봇 관리 페이지에는 더 큰 프리뷰를 둔다.**
평소에는 고정하고 호버 시 살짝 회전시키며, 후속 사용자 요청에 따라 클릭 후 드래그로
원하는 방향을 직접 조정할 수 있게 구현했다. 드래그한 방향은 유지한다.
표시 모델은 접힌 대기 자세와 외장 시안을 사용한다.
2~6절은 브랜치 분리 당시 실험 기록이고, 배치는 9절, standby 병합은 10~11절에 기록한다.

## 2. 브랜치 분리 방식

| 커밋 | 내용 |
|---|---|
| `ce385ae` | 3D 구현이 의존하는 미커밋 대시보드 UI를 기반 스냅샷으로 저장 |
| `ba7152b` | 3D 뷰어, 경량 모델, 대시보드 연결, 테스트와 niri 캡처 저장 |

- 원래 `feat/facility-dashboard` 워크트리에는 기존 대시보드 작업을 남기고 3D 변경만 분리했다.
- 따라서 이 브랜치의 전체 변경을 모두 3D 작업으로 해석하면 안 된다. 3D 변경 검토는 `ba7152b`를 기준으로 한다.
- 원본 CAD·ROS 모델은 수정하지 않았다. 브랜치 분리 시점에 원격 푸시는 하지 않았다.

## 3. 구현한 내용

### 모델과 자산

- 원본: `asm17-moving-agent/cleany`의 `e718ac57e861f3d34b6e0e10b0d18d87a348bf51`.
- 해당 커밋의 MJCF와 mesh를 사용해 기본 자세(`qpos0`)를 정적 GLB로 변환했다.
- 충돌용·비표시 형상을 제외하고, geometry 배치와 재질 색상을 반영했다.
- ROS/MuJoCo의 Z-up을 glTF의 Y-up으로 변환했다.
- 원본 GLB와 별도로 웹용 geometry를 단순화했다. 관절의 실시간 움직임이나 센서 상태는 연결하지 않았다.
- 같은 웹 모델의 Firefox 화면을 niri로 캡처하고 모델 영역을 잘라 정적 WebP 포스터를 만들었다.

### 화면과 렌더링

- 로봇 상세 패널과 로봇 관리 페이지에 모델 카드를 추가했다.
- 기본은 포스터이며, 클릭한 뒤에만 Three.js와 GLB를 로딩한다.
- `/robot-model`에 독립 탐색 화면을 추가했다. 기존 운영 화면의 최소 폭 설정과 분리해 좁은 창에도 대응했다.
- 입체·정면·측면·상단 보기, 회전·확대, 윤곽 보기, 절전·고화질 선택을 구현했다.
- 조작과 크기 변경 등이 있을 때만 렌더링하며, damping이 끝나면 멈춘다.
- 화면 밖 또는 숨겨진 탭에서는 렌더링을 중지한다.
- 기본 DPR은 1, 고화질은 최대 1.5다. 실시간 shadow map 대신 고정 바닥 음영을 사용한다.
- 3D를 닫으면 canvas와 GPU 자원을 해제한다. 로딩 오류·WebGL 오류 안내와 재시도도 포함한다.

## 4. 최적화 결과와 한계

| 항목 | 변환 원본 | 웹용 |
|---|---:|---:|
| GLB 용량 | 6,803,816 bytes | 2,926,432 bytes |
| 고유 geometry의 삼각형 합계 | 375,110 | 159,586 |

파일 용량은 약 57% 감소했다. 고유 삼각형 합계는 반복 배치 전 수치이므로
실제 한 프레임에서 그리는 삼각형 수와 다르다. 네이티브 화면의 진단 표시에서는
draw call 129회, 렌더링 삼각형 269,381개를 확인했다. 부품 병합이나 인스턴싱으로
draw call을 줄이는 최적화는 별도로 진행하지 않았다.

유휴 상태의 시간차 niri 캡처에서 누적 frame 수가 3회로 유지되는 것을 확인했다.
이는 계속 렌더링하지 않는다는 근거이며, GPU 사용률·메모리·소비전력의 감소율을
측정한 결과는 아니다. GLB 압축 디코더를 사용하는 전송 압축도 적용하지 않았다.

## 6. 검증과 재실행

브랜치 분리 후 새 워크트리에서 아래 명령을 실행했다.

```bash
pnpm install --frozen-lockfile
pnpm test
pnpm build
```

- 테스트 28개 통과, TypeScript 검사와 production build 성공.
- 빌드에서 지연 로딩되는 Three.js 관련 청크의 500 kB 초과 경고는 남아 있다.
- niri 캡처로 모델 배치·기본 크기·좁은 창 표시를 반복 확인했다.
- 네이티브 캡처를 자동 E2E 테스트나 모든 조작·오류 경로의 검증으로 간주하지 않는다.
- 최적화 스크립트로 다시 생성한 GLB는 저장된 웹용 GLB와 SHA-256이 일치했다.

개발 서버는 이 워크트리에서 실행하고 출력된 주소의 `/robot-model`을 연다.
기존 서버와 겹치지 않도록 포트를 지정할 수 있다.

```bash
pnpm --filter @cleany/dashboard dev --port 5175 --strictPort
```

개발 모드에서 `/robot-model?renderStats=1`을 열면 누적 frame 수와 렌더링 통계를 표시한다.
이 진단 표시는 production build에서는 비활성화된다.

## 7. 분리 당시 제안 — 후속 요청으로 조정

사용자 피드백에 따라 탐색 기능을 덜어내는 것이 다음 작업이다.

1. 별도 탐색 페이지와 회전·확대·윤곽 등의 조작 버튼을 제거하거나 실험 전용으로 격리한다.
2. 로봇 상세 카드에 작은 모델을 고정 각도로 배치한다.
3. 마우스 호버 중에만 천천히 회전시키고, 벗어나면 기준 각도로 복귀한 뒤 렌더링을 멈춘다.
4. 좌우 약 ±10~15° 움직임은 제안값이며, 실제 화면에서 조정한다.
5. 터치 기기와 `prefers-reduced-motion` 설정에서는 고정 표시한다.
6. 홈·목록은 정적 이미지 위주로 유지하고, 실제 텔레메트리와 단순 시각 효과를 구분한다.

위 목록은 분리 당시의 제안이다. 이후 사용자가 호버 회전과 클릭 후 드래그 회전을
함께 요청해, 수동 회전과 그 방향 보존을 추가했다.

## 8. 상세 카드 프리뷰와 직접 회전 — 2026-09-08

- 상세 패널은 로봇 이름 아래에 160px, 로봇 관리 페이지는 상태 정보 옆에 216px 프리뷰를 배치한다.
- 포스터를 먼저 표시하고, 마우스 사용이 가능한 기기에서 화면 근처에 들어온 카드만
  Three.js와 기존 웹 GLB를 로딩한다. 홈 목록과 지도는 기존 정적 표시를 사용한다.
- 호버하면 수평 12°, 위쪽 2°로 부드럽게 회전한 뒤 멈춘다. 반복 자동 회전은 하지 않는다.
- 왼쪽 드래그는 현재 표시된 각도에서 시작한다. 수평 회전과 8~65°의 카메라 고도를
  허용하며, 포인터 캡처로 카드 밖에서 놓아도 드래그를 종료한다.
- 드래그 후에는 선택한 방향을 유지하고, 이후 호버는 그 방향을 기준으로 적용한다.
  단순 클릭은 방향을 바꾸지 않는다. `처음 각도`와 `Home`은 기본 시점으로 돌아간다.
- 방향키로도 회전한다. 터치 전용 기기는 정적 포스터를 사용한다.
  동작 줄이기 설정은 자동 회전과 보간을 끄되 직접 회전은 즉시 반영한다.
- 확대·이동·윤곽·화질·시점 프리셋과 별도 탐색 화면 링크를 제거했다.
  `/robot-model`은 개발 모드에서만 접근하는 동일 컴포넌트 확인 화면으로 남긴다.
- 보간이 끝나면 프레임 예약을 멈춘다. 화면 밖과 숨긴 탭에서도 정지하며,
  상세 패널을 닫으면 이벤트·observer·canvas·GPU 자원을 해제한다.
- 다운로드 실패나 WebGL 오류는 포스터로 복귀하고 재시도를 제공한다.

상호작용 계산은 `robot-model-motion.ts`, DOM 입력과 렌더링은
`RobotModelCanvas.tsx`, 로딩 및 포스터 복구는 `RobotModel.tsx`에서 관리한다.
기존 CAD·GLB와 Backend 계약은 변경하지 않았다.

검증 명령:

```bash
pnpm --filter @cleany/dashboard test src/components/RobotModel.test.tsx src/components/robot-model-motion.test.ts src/pages/HomePage.test.tsx
pnpm contracts:check
pnpm test
pnpm build
pnpm --filter @cleany/dashboard test:robot-model
```

브라우저 검사는 `playwright.robot-model.config.ts`의 Vite 5176과 API fixture를 사용한다.
Chromium 실행 파일은 필요 시 `PLAYWRIGHT_CHROMIUM_EXECUTABLE`로 지정한다.
이 검사는 소프트웨어 WebGL의 동작 검증이며 GPU 사용률·전력 측정을 의미하지 않는다.

이번 변경의 검증 결과:

- 관련 단위 테스트 13개, 전체 단위 테스트 38개 통과.
- `pnpm contracts:check`, TypeScript를 포함한 production build와 `git diff --check` 통과.
- Playwright 8개 통과: 호버·드래그·각도 유지·복귀·키보드, 카드 밖에서 드래그 종료,
  동작 줄이기, 터치 정적 표시, GLB 다운로드 실패·재시도, WebGL context 손실·복구,
  홈 상세 패널의 표시 순서·스크롤 시 렌더링 중지·닫기, 다운로드 중 닫기.
- 별도 Mock Backend와 production build에서 48석 지도, 상세 프리뷰 조작,
  진단 속성 비활성화와 개발 전용 경로의 홈 리다이렉트를 확인했다. 브라우저 예외는 없었다.
- 1366×768 상세 패널에서 지도 조작 버튼이 프리뷰를 가리지 않으며, 모델·배터리·마지막
  확인 정보가 함께 표시되는지 추가 검사했다.
- Three.js를 포함한 지연 청크는 약 570 kB이며 기존 500 kB 초과 빌드 경고는 남아 있다.

## 9. 홈 목록과 관리 페이지로 배치 정리 — 2026-09-09

사용자가 승인한 배치에 따라 홈 로봇 카드의 오른편에 106×108px 프리뷰를 둔다.
1280px 이하 화면에서는 모델 폭을 90px로 줄이고 이름 영역을 확보한다.
이름·상태 버튼과 모델은 서로 다른 요소이므로 모델을 클릭하거나 드래그해도 상세가 열리지 않는다.
이름 버튼은 기존 상세 열기·닫기를 유지한다.

홈 상세 패널은 상태, 마지막 확인, 현재 작업과 위치 정보를 표시한다.
상세를 닫아도 목록 모델과 사용자가 맞춘 각도를 유지하며, 홈을 떠나면 모델을 해제한다.
로봇 관리 페이지의 216px 프리뷰와 지도의 2D 아이콘은 유지한다.

목록에서도 화면 근처의 모델만 로딩하고, 스크롤로 가려진 모델의 렌더링은 멈춘다.
프레임 사이의 실제 경과 시간으로 호버를 보간한다. 네이티브 Firefox 확인 중
약 1초 간격의 화면 갱신이 관측되어, 짧은 회전이 과도하게 늘어나던 시간 상한을 제거했다.
느린 화면 갱신 자체의 원인은 확정하지 않았으며 GPU 성능 측정 결과로 해석하지 않는다.

README에 배치·상호작용·해제 시점을 갱신했다. Backend 계약과 KB는 변경하지 않았다.

검증 결과:

- 전체 Vitest 38개 통과. 회전 시간 보정 뒤 관련 motion 테스트 7개도 다시 통과했다.
- Playwright 10개 통과. 기존 회전·오류 복구 검사에 홈의 클릭/드래그 분리,
  상세를 닫은 뒤 각도 유지, 목록 스크롤에 따른 지연 로딩·렌더링 중지,
  다운로드 중 홈 이탈, 500ms 간격의 느린 프레임에서 회전 종료를 포함한다.
- `pnpm contracts:check`, TypeScript를 포함한 production build, `git diff --check` 통과.
  Three.js 지연 청크의 500 kB 초과 경고는 남아 있다.
- niri의 `screenshot-window`로 일반 Firefox의 홈·로봇 관리 창을 캡처하고 배치를 확인했다.
  아래는 네이티브 화면 캡처이며, 자동 조작 검사는 별도의 Chromium 소프트웨어 WebGL 결과다.

## 10. standby 외장 시안 병합 — 2026-09-09

## 13. 상세 모델의 회전 안내 — 2026-09-09

모델 카드의 상단 문구와 하단 구분선을 제거하고, 준비된 3D 모델에는 오른쪽 아래
`드래그하여 회전`만 표시한다. 자세 미연동 설명은 스크린 리더용으로 남기며,
초기 각도 복귀와 로딩 재시도는 접근 가능한 이름이 있는 아이콘 버튼을 사용한다.

홈의 상세 패널과 로봇 관리 상세에만 `rotationGuide`를 켠다.
첫 안내는 1.6초 후 시작하고, 수평 22° 회전했다가 기준 각도로 돌아오는
2.6초 동작을 재생한 뒤 6.5초 쉬고 반복한다.
`RobotRotationGuide.ts`에서 로봇 중심의 바닥 원을 현재 카메라로 투영해 SVG 원호를 그린다.
원호는 오른쪽에서 왼쪽으로 최대 120°(원의 1/3)까지 길어졌다가 같은 경로로 짧아진다.
양 끝 화살촉은 항상 반대 방향을 가리키며, 모델 회전과 원호 길이는 같은 진행값을 따른다.
화살촉의 양 날개도 원호와 같은 3D 바닥면에서 투영해 바닥 원근에 맞춰 눕힌다.
원호가 너무 짧을 때는 화살촉이 겹치지 않도록 숨기며, 반복 사이에는 화살표도 사라진다.
전체 원형 궤도는 표시하지 않고, 모델의 표시 크기는 안내 추가 전과 동일하게 유지한다.
시간과 각도는 `robot-model-motion.ts`의 `ROTATION_GUIDE`에서 관리한다.

호버와 키보드 포커스 중에는 안내를 쉬고, 드래그·방향키·초기화 조작을 시작하면
해당 모델이 닫힐 때까지 반복 안내를 중단한다. 드래그는 표시 중인 각도에서 이어진다.
동작 줄이기 설정, 창 비활성화, 화면 밖에서는 안내를 재생하지 않으며,
반복 사이에는 연속 프레임을 예약하지 않는다. 왼쪽 목록에는 안내를 적용하지 않는다.
현재 왼쪽 목록은 정적 썸네일을 사용하며 WebGL 모델은 상세를 열 때 불러온다.

검증: 관련 단위 테스트 14개, 모델 브라우저 검사 12개, 계약 검사와 빌드 통과.
브라우저 검사는 Chromium SwiftShader에서 원호 변화·왕복 반복·직접 조작·동작 줄이기·
화면 밖 정지와 상세 종료를 확인했다. Firefox에서는 `localhost:5173/robots`를 열고
niri 연속 창 캡처로 양방향 원호의 확장, 회전 중 배치와 원래 각도 복귀를 확인했다.
